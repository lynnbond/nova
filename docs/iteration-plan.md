# Nova 工作流引擎 — 后续迭代计划

> 目标：做一个**纯粹的工作流引擎**，砍掉所有 OA 系统功能
> 砍掉的 Pandora OA 特性：关注系统、行为分析、备份/化身处理人、申请说明、移动端级别、邮件审批、按钮屏蔽/UDC/管道类/决策过滤器

---

## Phase 0 ✅ 已完成

- 核心引擎（状态机 + 调度器 + Hook）
- SQLite 持久化（9 张运行时表）
- ProcessBuilder 链式 API
- React UI 框架（iam server `release/3.x-lts` 风格）
- 流程设计器 V1（React Flow，节点尺寸已调优，开始/结束图标化）

---

## Phase 1 🔜 让一条流程真正跑起来

> 目标：用户能创建一个实体、提交、流转、完结，形成完整闭环

**工作流管理**
- 实体 CRUD API（创建草稿 → 提交 → 推进 → 完结 → 撤销）
- 实体列表/详情页（待办、在途、已完结）
- 提交交互（submit / preSubmit：选择下一环节、选择处理人）
- 待办列表（按处理人查询）
- 已办列表（按处理人查询）
- 处理日志精简版（谁、什么时候、做了什么）

**前端**
- 工单管理页（列表 + 详情 + 操作）
- 待办事项页
- 发件箱/已办页
- 提交流程交互（环节选择、处理人选择）

**后端**
- 实体 CRUD handler
- 提交/预提交 handler（含环节选择反馈、处理人选择反馈）
- 待办/已办查询 handler
- 处理日志查询 handler

## Phase 2 📋 流程定义管理（后端）

> 目标：设计器保存的流程真正可用，不丢数据

**流程 CRUD API**
- 流程定义创建/列表/编辑
- 活动（节点）属性 CRUD（名称、类型、处理人规则）
- 活动链接 CRUD（连线：谁连谁、前进/回退）
- 流程版本管理（保存草稿 → 发布 → 新版本）

**后端**
- 流程定义持久化到数据库（不再用内存 mock）
- 版本管理：v1 草稿 → v1 已发布 → v2 草稿
- ProcessBuilder 从数据库重建流程定义

**前端**
- 设计器保存 → 后端持久化
- 已发布流程转为只读
- 版本切换查看

## Phase 3 🔄 丰富的流程控制

> 目标：支持真实场景的分支、汇聚、退回、并行

**退回机制**
- 活动链接 LINK_TYPE=2（回退路径）
- 退回操作 API（退回指定前驱环节）
- UI 退回按钮 + 选择退回目标

**汇聚/等待运行时**
- CONVERGE 节点：等待所有分支到达后再前进
- WAIT 节点：等待外部事件（超时/回调）
- TAIL 节点：任意分支到达即触发

**处理人规则引擎**
- DEPT_BASED — 按部门
- TEAM_BASED — 按团队
- ROLE_BASED — 按角色
- TASK_BASED — 按环节（传递上一环节处理人）
- 策略：SINGLE / COUNTERSIGN / EXCLUSIVE

**多人策略**
- 单人处理（谁先受理谁处理）
- 会签（所有人处理完才前进）
- 排他（一人处理即可）

## Phase 4 💬 意见与展示

> 目标：用户能写审批意见、查看历史意见、查看流程图

**意见/留言系统**
- 意见 CRUD（增删查，支持追回意见？）
- 意见列表展示
- 强制意见开关（环节级别的 `IS_FORCE_OPINION`）

**流程图展示**
- 流程图中嵌入处理状态（当前环节高亮、已完成变灰）
- 只读模式查看流程图

**处理日志展示**
- 按时间线展示实体完整处理轨迹
- 每个步骤的活动名称、处理人、时间、意见
